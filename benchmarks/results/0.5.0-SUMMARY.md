# ASTra 0.5.0 benchmark summary

Runs: GitHub Actions run 43457976873 (all experiments, commit 2ed7a3b of this branch) and run 43466748250 (E3 only, re-run after a harness fix, PROTOCOL.md D5). Baseline: published `@attentionform/astra-mcp-server` 0.4.2. Build: tag `cli-v0.5.0` (commit 8a29aaf, the commit the 0.5.0 packages were published from), built on the runner; it is the released source, not a download of the npm package. Machine: GitHub-hosted `ubuntu-latest`, 4 vCPUs, one VM per job. Timings are compared only inside the `perf-*` folders, where both versions ran alternately on one VM. Everything below is computed from the raw `*.jsonl` files next to this file; `REPORT.md` in each label folder is the generated full report.

**All documents are generated by scripts (python-docx and LibreOffice), not written in Word. All faults in E3 are injected by our own script. Counts here say nothing about how real-world files behave.**

## E9 Original recovery (new in 0.5.0), 40 documents

| Check | 0.5.0 build |
| --- | --- |
| Original available after open | 40 of 40 |
| Export before any edit has the SHA-256 of the file on disk before the first open | 40 of 40 |
| Same, exported after an edit and a save (the edit changed the file in 40 of 40) | 40 of 40 |
| Working file after `restore_original_document` has that SHA-256 | 40 of 40 |
| Errors | 0 |

0.4.2 has no recovery tools; all 40 rows are recorded as `tool_unavailable`.

## E10 Two writers, one file (30 trials)

Two MCP server processes open the same file, each replaces a different paragraph, both save at the same time. No pass threshold: one writer per document is a documented limit.

| | 0.4.2 | 0.5.0 |
| --- | --- | --- |
| Both edits survive | 0 of 30 | 0 of 30 |
| One edit lost | 11 of 30 | 9 of 30 |
| Neither edit in the file | 17 of 30 | 19 of 30 |
| File unreadable | 2 of 30 | 2 of 30 |
| Trials with a save error | 10 of 30 | 21 of 30 |
| `git fsck` failures | 0 of 30 | 0 of 30 |

Save errors are all `history commit failed, file restored` (isomorphic-git). The count varied between runs and machines (10 to 21 in CI, 11 to 16 locally) with no consistent difference between versions.

Small documents (1 and 10 pages) opened 13 to 14 percent slower on first open, in line with the fixed cost of storing the original.

## Other experiments

Edit locality, atomicity, schema faults, history and representation are in `REPORT.md` of each label folder. Both versions give the same results for edit locality (0 of 1,047 edits changed another paragraph), atomicity (108 of 108 rejected batches left the document unchanged) and the outline size ratio (2.89 against a goal of 3, not met). The schema check flagged 129 of 158 faults we injected ourselves into three generated documents (goal 95 percent, not met, same on both versions). Whole-file byte-exact restore by `revert` is 0 of 300 by design; package parts are identical in 300 of 300 (189 of 300 in 0.4.1). Original recovery is E9 above.
