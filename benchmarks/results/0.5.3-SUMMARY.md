# ASTra 0.5.3 benchmark summary

Run: GitHub Actions run 43848385189 on branch `bench/053` (all experiments, one run). Build under test: commit e03c87c on `main` (the commit the 0.5.3 packages were published from; the release tag `cli-v0.5.3` points at it), built on the runner; it is the released source, not a download of the npm package. Baseline: published `@attentionform/astra-mcp-server` 0.4.2 (pinned in `benchmarks/package.json`), run in the same workflow. Machine: GitHub-hosted `ubuntu-latest`, 4 vCPUs, one VM per job. Timings are compared only inside the `perf-*` folders, where both versions ran alternately on one VM. Folders: `0.5.3-build-e03c87c` (build), `0.4.2-hosted-runner-053` (baseline of this run), `perf-0.4.2-published-053-r1/r2` and `perf-0.5.3-build-e03c87c-r1/r2` (timings), `perf-sequence-053.log`. The folders of the 0.5.0 and 0.5.2 runs are unchanged and are not part of this one. `REPORT.md` in each label folder is the generated full report; numbers below come from the raw `*.jsonl` files and those reports.

**This benchmark does not measure the charts, tables or page layout added in 0.5.3, and its documents are not Word files with other namespace prefixes.** It shows that the 0.5.3 changes did not move the results measured before.

**All documents are generated by scripts (python-docx and LibreOffice), not written in Word. All faults in E3 are injected by our own script. Counts here say nothing about how real-world files behave. The Word page renderer added in 0.5.2 is not measured here.**

## E10 Two writers, one file (30 trials)

Two MCP server processes open the same file, each replaces a different paragraph, both save at the same time. No pass threshold: one writer per document is a documented limit.

| | 0.4.2 | 0.5.3 |
| --- | --- | --- |
| Both edits survive | 0 of 30 | 0 of 30 |
| One edit lost | 11 of 30 | 4 of 30 |
| Neither edit in the file | 17 of 30 | 26 of 30 |
| File unreadable | 2 of 30 | 0 of 30 |
| Trials with a save error | 10 of 30 | 13 of 30 |
| `git fsck` failures | 0 of 30 | 0 of 30 |

The save-error count varied between runs (10 to 30 in CI) and so did the split between one edit lost and neither saved, with no stable difference between versions; do not read the 0.4.2 versus 0.5.3 difference as an improvement. Two writers on one file are not coordinated in 0.5.3 either.

## Other results (from REPORT.md)

- Reading cost (R1): median outline ratio 2.89x, bootstrap 95% confidence interval 2.61 to 4.30, range 1.70 to 25.64.
- Creating from Markdown (C1, 26 trials): all saved and valid; the Markdown an agent writes is a median 12.8x fewer tokens than the XML for the same document.
- Building with typed operations (C2): 15 of 15 recipes built and passed the independent checkers.
- Schema gate (E3): strict mode refused every caught fault (126 of 126); the save-time normalizer repaired 14 more (element-order faults), so 143 of 158 were caught or repaired. Not flagged: 15 of 158 faults (identifier, missing-element and package classes). Default mode wrote the file for 112 of 126 caught faults because those faults were already in the input; it refuses edits that add new errors.
- Atomicity (E4): 144 batches, 108 rejected, 36 accepted (an unknown style name is not an error). Of the 108 rejected, 72 exercised the engine rollback and 36 were refused earlier by the tool input schema.
- History (E5): redo returned the head state exactly in 300 of 300; `preview_revert` named exactly the changed parts in 300 of 300; by-steps reverts 40 of 40. History store of a 5-page document: 0.94 MB at start, 1.02 MB after 30 saves (22 to 28 times the size of the .docx).
- Locality of the first save: a file written by another program has its XML re-serialised on first save in 100% of paragraphs (raw bytes), while content stays identical in 100% of paragraphs once identifier attributes are ignored; text identical in 40 of 40.
