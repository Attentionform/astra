# Changelog

All notable changes to ASTra are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the packages use [Semantic Versioning](https://semver.org/). While the major version is 0, minor releases may change behavior; each such change is listed.

Packages released together: `@attentionform/astra-engine`, `@attentionform/astra-mcp-server`, `@attentionform/astra` (command line) and `@attentionform/ooxml-validator`, all at the same version.

## [Unreleased]

### Added

- A Word renderer for Windows. `--renderer auto|word|libreoffice` (`astra visual`, `inspect --visual`, `export --format pdf`), env `ASTRA_RENDERER`, and the MCP parameter `renderer` on `visual_inspect` and `export_document` choose the program that turns the document into a PDF. `auto` is LibreOffice on every platform, so nothing changes unless `word` is named. `word` needs Microsoft Word 2010 or later on Windows. ASTra starts its own hidden Word through PowerShell, opens a copy read-only with a made-up password (a password prompt can never appear), saves a PDF and closes Word with `Quit()`. It never ends Word by force and never touches a Word the user has open. A named renderer never falls back; a missing Word stops with `E_DEPENDENCY` and a remedy. A password-protected document is refused with `E_VALIDATION` before Word starts.
- A Windows page-image renderer. `--pdf-to-image auto|windows|poppler`, env `ASTRA_PDF_TO_IMAGE`, MCP `pdfToImage` on `visual_inspect`. On Windows, `auto` now draws pages with the renderer built into Windows 10 and later and falls back to Poppler when it cannot; elsewhere `auto` is Poppler as before. The Windows renderer needs no install and matches Poppler's page size within one pixel. It draws the crop box where Poppler draws the media box.
- Network references are neutralised before a render. A linked image, an attached template, a linked sub-document, a mail-merge source and the fields `INCLUDETEXT`, `INCLUDEPICTURE`, `LINK`, `IMPORT`, `DDE` and `DDEAUTO` are changed on a copy of the document before LibreOffice or Word sees it, so a render contacts no network location (a UNC path could send the user's Windows login hash). The original file is not changed. `--allow-network-references` (and `--no-allow-network-references`), env `ASTRA_ALLOW_NETWORK_REFERENCES`, and the MCP parameter `allowNetworkReferences` turn this off for one call. A document ASTra cannot inspect with certainty (a `DOCTYPE`, malformed XML, duplicate parts, a UTF-16 part that cannot be decoded, a non-zip input). Parts stored as valid UTF-16 are read as UTF-16 (also when white space comes before the first tag), and a part that has to be rewritten keeps its encoding. An `.xml` part in UTF-32 is refused. The size check for this scan applies the total-size ceiling only, not the per-entry compression ratio, so a document with a blank bitmap still exports is refused with `E_SECURITY`. See the security guide, section 7.
- Results report what ran: `renderer` and `rasterizer` (`requested`, `used`, and `fallbackFrom` and `fallbackReason` when `auto` fell back) and `references` (what was changed, counts and up to 50 entries without any host or path). The command line prints a `note:` line on stderr for a fallback or a change, and the MCP tools return `notes`.

### Changed

- The environment variables, the command line flags and the MCP parameters follow one rule: a value given for the call beats the variable. An invalid variable value is an error that names the variable.
- `inspect --visual` and `visual_inspect` now say `a missing renderer or Poppler` where they said `LibreOffice or pdftoppm`, because the missing program depends on the choice.
- `astra export` takes `--renderer` and the network flags only for PDF; for HTML and Markdown they are a usage error.

## [0.5.1] - 2026-11-14

Ten npm packages move to 0.5.1: `@attentionform/astra-engine`, `@attentionform/astra-mcp-server`, `@attentionform/astra`, the `@attentionform/ooxml-validator` wrapper and the six native validator binaries. The validator itself did not change. This release makes `astra visual` and PDF export work on Windows and macOS, exports files with only element-order errors, refuses a bad colour, highlight or size at the call, adds a headings-only `outline` view of a document, and explains how to read a document cheaply.

### Added

- `astra inspect --outline` (same as `--fidelity outline`) and `inspect_document` with `fidelity: "outline"` list the headings only: `ID | L | Style | Text | Section`, where L is the heading level and Section is the chain of headings above it, nested by level. A heading is a body paragraph whose own style id contains `heading`, `title` or `subtitle` (the rule `isHeading` already used): `Heading4` is level 4, `Subtitle` 2, `TOCHeading` 1; a custom style such as `Kapitel`, a heading inside a table cell and a textbox host paragraph are not listed. Text is cut at 80 characters unless `--max-text` / `maxTextLength` is set. `--width` and `--wrap` fold the Text column of the outline like the other tiers (the `--json` `toon` field stays one line per heading); a row whose Section cell leaves no room stays on one line. A pipe, backslash or line break in a heading is escaped in the `Text`, `Style` and `Section` cells (`\|`, `\\`, `\n`), and a `>` in an ancestor heading is written `\>` in `Section`, so a row always splits into five cells. `rowCount` and `totalNodes` count heading rows for this tier, so the response adds `outline` (`headings`, `nodes`, `tables`, `images`, `words` for the whole document); the CLI footer and `--json` carry the same counts. `aroundNode` on a node that is not a heading shows the heading above it and reports `aroundResolvedTo` (`null`, with a `note`, before the first heading or when the document has none).

- New page `docs/reading-documents.md`, "Reading a document cheaply": which control to use to read less (the outline, `aroundNode`, paging, `maxTextLength`, `maxTokens`, `sectionId`), what counts as a heading, and sizes measured on a generated document with `scripts/measure-read-tiers.mjs`.

### Changed

- `compose_document` with `template` into a document that is not that template's seed now says both ways out: call it again without `template` to append, or call `new_document` with the template first. The tool description says the same.
- An operation whose action is a verb plus an action name (`setTable`, `addImage`, `deleteTable`) now gets a suggestion. The error names the closest action, or both candidates when the verb is also an action (`deleteTable`: `table` or `delete`), then lists that action's keys and its operations.
- A batch that fails on an id that `compose_document` could have minted (`md_0002`, `md2_0001`, `md_10000`) now says what the id is and how to go on: use the paragraph id from `persistentIds`, find the text with `search_content`, or re-read ids with `inspect_document`. The message lists a reopen, a typo and a deleted node as possible causes and does not claim one. Other missing ids keep the existing message.
- A colour, a highlight or a size that no writer can use is now refused when the operation is checked, with a message that names the field and lists the accepted forms. Before, `color: "banana"`, `highlight: "pink"`, `fontSize: 9999`, a page border `sz: "12pt"` and similar values passed the check and failed after the whole batch had run, with a raw XML message from the validator. A colour is six hex digits (optionally with `#`), `auto` (text, page border, rule and table border colours), or one of ten names mapped to a fixed value: `red` FF0000, `green` 008000, `blue` 0000FF, `black` 000000, `white` FFFFFF, `yellow` FFFF00, `orange` FFA500, `gray` and `grey` 808080, `purple` 800080. The same rule is applied by the writers, so a value with surrounding spaces (`" #FF0000"`, which used to be written with the `#` and fail) and a colour name are written as hex. Table fill, header fill, text colour and border colour accept the names too; chart series and watermark colours map a name and keep their fallback for any other value (the style guide palette colour for a chart series when a guide is set, `D1D5DB` for a watermark). `highlight` is limited to the 17 values of the specification. A font size is limited to Word's 1638 pt. A border width (`pageBorder` `sz`, table `sz`) is a whole number of eighths of a point from 1 to 96, and a string such as `"12pt"` is no longer accepted there. The accepted forms of every colour and size field are listed in the CLI guide.
- A border width is now checked where it is written, not only in the schema: the nested `params` of a `table` `setBorder` (`params: { sz: 1000 }` wrote a width Word cannot hold), the border configs of a `style` operation (`borderBox: { sz: 1000 }`) and `pageBorder` all require a whole number from 1 to 96. A `setBorder` width of `0` was written as 4 without a word and is now refused.
- `astra stats` and the `astra inspect` footer printed `pages~N (est, 500 wpp)` and a recipe of `ceil(words/500)`, but the estimate has used 450 words a page plus fixed weights (0.45 page per table or callout, 0.5 per image, 1 per page break). The label now reads `(rough estimate)` and the recipe matches the code. When tables, images or page breaks add to the estimate, a line says how many pages come from them and that the estimate cannot size them. `astra stats --json` and the MCP `get_stats` result carry `pageTerms` (`words`, `tables`, `images`, `pageBreaks`, in pages, rounded to two decimals). The estimate itself is unchanged; use `astra visual` or `visual_inspect` for the renderer's page count.
- `astra export --format pdf` now checks the package limits (`ASTRA_MAX_RATIO`, `ASTRA_MAX_UNCOMPRESSED_BYTES`, the same ceilings as opening a document) before it validates or renders, for every input. A valid package over a ceiling that was rendered before now stops with `E_LIMIT` and the remedy that names the setting.
- The heading level of a styled paragraph is now the real one. `Heading4` to `Heading9` reported level 1 and `Subtitle` reported level 1; they now report 4 to 9 and 2 (`Heading1` to `Heading3` and `Title` are unchanged). A style that only contains the word, such as `TOCHeading`, keeps level 1. Which paragraphs count as headings is unchanged, except that a table or a textbox host paragraph no longer takes the style of a paragraph nested inside it, so a table with a heading-styled cell is no longer reported as a heading. The level shows in the structural summary (`isHeading`, `headingLevel`).

### Fixed

- `astra visual` and `astra export --format pdf` now find LibreOffice and Poppler on Windows and macOS: the lookup matches `.exe` and `.com` names on Windows and falls back to the standard install folders (Program Files, `LibreOffice.app`, Homebrew, MacPorts) when `PATH` has no match; PDF export no longer calls `which`, which does not exist on Windows. The error text names an install route for each system.
- The style shown for a table, and for a paragraph that holds a textbox, is no longer the style of a paragraph nested inside it. Before, a table with a `Heading2` cell printed `Heading2` in its `inspect` Style column and counted as a heading for a table of contents; it now reports no style of its own, like any table.
- `astra export <file> --format pdf` no longer refuses a file whose only schema errors are the order of child elements (for example `w:color` after `w:sz` in a run's properties, which Word accepts). The export validates the file first. A valid file is rendered as it is. A file with order errors is rendered from a temporary copy in which only that order is corrected; a separate check proves that nothing else differs, every other part is copied unchanged, the copy must validate, and the source file is never written. The command prints a note saying the PDF came from a corrected copy. Anything else (a real schema error, an error that needs a rename or a default value, a part that is not UTF-8, a duplicate or unsafe package entry) is refused before the renderer starts, with a remedy that points to `astra validate` and `astra normalize`. The MCP `export_document` tool is unchanged: it renders the session as a save would write it.

## [0.5.0] - 2026-11-13

All ten npm packages move to 0.5.0. This release adds recovery of the exact original file: ASTra keeps the bytes of a document when its history is first created, and you can export them or restore them in place as one recorded step. History now also stops, with nothing written, when a package part cannot be collected. The MCP server serves 21 tools (two new: `export_original_document` and `restore_original_document`). Histories written by 0.5.0 are not meant to be shared with 0.4.x (see Known limits).

### Added

- Exact original DOCX capture when new history is initialized, with SHA-256 verification and explicit availability status. The CLI remains opt-in with `history --init`; histories created before this feature are not migrated.
- Original-file export and in-place restore through the MCP tools and `astra history --export-original <out>` / `--restore-original`. Export preserves original bytes without changing the working document. Restore refuses conflicting disk changes and records history. Normal saves and ordinary revert/redo still serialize document states.

### Changed

- First history creation is serialized with an exclusive `.astra-init.lock`. A process killed during creation can leave it; ASTra then refuses writes that would record history, before touching the file, and names the lock, its creator and the steps to clear it. ASTra never removes the lock and never waits for it. A history that has no commits yet refuses `--init` when a retained original from different bytes is already there (`E_CONFLICT`, both kept).
- A package snapshot that cannot be collected now stops the history commit that needed it (first history creation, save, revert, redo and original restore, and every commit the editor library makes) and reports it. An empty set of parts is never recorded in its place. A save checks this before it writes the file. Before, an empty set of package parts could be committed as a complete snapshot, which a later revert would trust. `batch` and `normalize` also refuse while a first-creation lock is held before the history folder exists.
- Opening a document through the MCP server is faster than in 0.4.2, because the document is serialized once per open and not at all when history already exists. Measured against the published 0.4.2 package, median of 16 opens per build on one machine: a 200-page file took 1.67 s instead of 2.14 s on first open (about 22 percent less, validation on) and 0.84 s instead of 1.66 s on reopen (about 49 percent less); with validation off, 1.66 s instead of 2.05 s and 0.72 s instead of 1.52 s. A 200-page file with 20 MB of media took 2.85 s instead of 3.10 s on first open, which is inside the run-to-run spread, and 0.81 s instead of 1.90 s on reopen. On a CI machine (four threads, prose files, median of 30 opens per build, two separate runs) the open took 14 to 16 percent less on 100 and 200 pages (first run: 371 ms instead of 442 ms and 627 ms instead of 745 ms; second run: 461 ms instead of 551 ms and 795 ms instead of 921 ms) and 8 to 15 percent less on 50 pages, but 4 to 14 percent more on 10 pages (second run: 244 ms instead of 214 ms) and 10 to 20 percent more on a 1-page file (second run: 224 ms instead of 186 ms), because storing the original is a fixed set of file operations (write, flush to disk, read back, hard link) that small files do not earn back: about 30 to 40 ms on the CI disk, 1 to 2 ms on a fast local disk, and it does not grow with the file. Saving and editing took the same time as in 0.4.2 within 6 percent, in either direction. Times depend on the machine and the file.

### Fixed

- `WorkerClient.close()` in the validator package no longer returns while a worker process it started and sent a signal to (a recycle, a timeout, a fatal reply or a failed write) is still running. It treated "a signal was sent" as "the process has exited", and a killed worker was dropped from its list at once, so on Windows the process could outlive `close()` for a short time (it made one platform test fail now and then).

### Known limits

- Two ASTra processes that save the same document at the same time are not coordinated; one can lose an edit, a save can fail with its file restored, and rarely a file can be left truncated. This is how 0.4.2 behaves as well and is not changed here. Use one writer per document.
- Do not run 0.4.x and 0.5.x on the same document at the same time.
- A location without hard-link support cannot store or export an original.

### Privacy

- The retained original can contain data later removed from the working document by sanitization. Sanitization does not erase the original or earlier history. Original storage counts toward the history quota.

## [0.4.2] - 2026-11-12

All ten npm packages move to 0.4.2. This release fixes how history restores a document: a revert now puts back every package part exactly as it was saved. The MCP tool names and input schemas are unchanged; the generated schema files carry the new version only.

### Fixed

- **A revert no longer leaves comment metadata behind.** History recorded only a fixed list of package parts, and the list did not include `word/commentsExtended.xml`, `word/commentsIds.xml`, `word/commentsExtensible.xml` or `word/people.xml`. After a revert past a comment, those parts stayed in the file. `word/people.xml` lists comment author names, so an author name could remain in the file after the comment was reverted away. Reverting to a commit with fewer authors also kept the later authors and left reply entries that pointed at comments that no longer existed. History now records every package part except `word/document.xml`, which is committed separately, and a revert restores all of them and removes parts the target commit does not have. This applies to the MCP tools (`revert_document`, `redo_document`, `preview_revert`) and to `astra revert`, `redo` and `preview-revert`.
- **A revert does not recompress parts that did not change.** The restore step rewrote every zip entry, which changed the stored (compressed) bytes of unchanged parts, such as an embedded thumbnail, even though their content was identical.
- **`sanitize_document` and `astra sanitize` also replace the display name in `word/people.xml`.** The author pass emptied `w15:author` but left the same name in `w15:userId` when the person has no account (`w15:providerId="None"`, which is what ASTra writes). So a document that kept its comments still carried the commenter's name in `people.xml` after a default sanitize. The pass now replaces that `userId` too (with `Anonymous` when the replacement author is empty, because the schema needs a non-empty value). An account id of a real provider is still handled by the PII pass, as before.

### Changed

- **Commits recorded by an older version are marked unknown.** A commit written by 0.4.2 or later carries a small marker file (`.astra-snapshot-format`) in its history, set only when the commit was proven to hold every package part of the snapshot it was given. Older commits have no marker. `preview_revert`, `revert_document` and the matching command-line commands now return `snapshotComplete` and, for an unmarked commit, a `restoreWarning`: the restore replaces only the parts that commit recorded and leaves every other part as it is in the current file, so the result is not an exact restore. Nothing is migrated. A new commit in an older history gets the marker; older commits stay as they were.
- **A part whose name git cannot store is recorded under an escaped name** instead of being left out. Names that start with `.git`, the name of the marker file and a root-level `document.xml` are affected. Directory entries carry no content and are not recorded.
- **`astra revert` treats a hand edit to any package part, `docProps` included, as a conflict.** Before, only the listed parts were compared with the last recorded commit. The comparison for a commit recorded by an older version still uses the older list.

### Privacy note

Files reverted with 0.4.1 can still contain `word/people.xml` with comment author names, and `commentsExtended.xml` with no comment behind it. In a test on a file made that way, the default `sanitize_document` of 0.4.2 removed the name from the file, and `stripComments` and `purgeAuthors` of 0.4.1 and 0.4.2 before this fix did not. `stripComments` alone keeps a `people.xml` that has no `comments.xml` beside it. This cleans the file you run it on. It does not change history stores in `.astra` folders, backups or other copies of the document.

## [0.4.0] - 2026-11-10

All ten npm packages move to 0.4.0, including the six native validator platform packages. The native validator source is unchanged; the platform packages are rebuilt so that they carry the licence terms for new versions.

### Added

- **A plain Markdown quote composes as a quote.** `> text` used to fail with "blockquotes are out of scope". It now becomes paragraphs in a real `Quote` paragraph style (left rule, italic, indented half an inch), so every quote can be restyled in one step in Word. A blank `>` line starts a new paragraph of the same quote, `> >` nests down to level 3 (a deeper level is written at level 3 with a warning that names the line), and flat lists and fenced code stay inside the quote. A table, heading, rule or image inside a quote fails with a line number and a reason. A `[!TAG]` marker that is not a known alert type fails with the list of valid tags. Every built-in template carries the `Quote` style, compose adds it to an opened document that lacks one (an existing `Quote` style is kept), and the Markdown export writes quote paragraphs back as `>` with their nesting.
- **A document can be built in several `compose_document` calls.** The first call of a session keeps the `md_0001` ids; a later call mints `md2_0001`, `md3_0001` and so on, so the ids never collide. A later call appends at the end by default and takes `anchor` (a node id, `start` or `end`) and `position` (`before` or `after`) to put the new blocks in the middle. `template` is accepted on the first call only. A failed compose now changes nothing as a whole; before, the chunks that ran before the failing one stayed applied. Citation numbers and the References list restart in each call.
- **`@start` and `@end` anchors are documented and need no `position`.** `start` and `end` already worked, but the schema and the tool descriptions did not say so, `@end` failed with "Anchor node not found", and `position` was still required. With `start` the position is `before` and with `end` it is `after`; an explicit `position` still wins.
- **`get_stats` and `astra stats` report `callouts`.** `astra stats` also prints and returns `tables` and `images`, so the command line and the MCP tool agree.
- **`save_document` returns `valid` and `errorCount`**, the same shape as `validate_document`. A refused save lists the first 10 errors with their `xPath` and points to `validate_document` for the rest.
- **`setCellTextColor` accepts `textColor`** as an alias of `color`, like `setShading` and `setCellShading`. The `operation` field of the table action now lists the parameters of every table operation.
- **The platform smoke runs in CI.** Every CI run installs the packed packages on the six systems that have a native validator (Linux x64 and arm64, macOS x64 and arm64, Windows x64 and arm64) and runs the CLI and the MCP server through the shims npm writes, through `npx`, and through an MCP handshake over stdio. The release workflow calls it before it publishes.

### Changed

- **Licence terms for new versions.** The free-use rules in `LICENSE` change from the next release on. The old small-business test (under USD 1,000,000 revenue and fewer than 10 people, also used for building ASTra into a product) is split into three. A person who works alone is free at any revenue, in any legal form. An organization's own internal use is free up to 10 people and under USD 250,000 revenue; above either limit it needs an internal licence. A product or service with ASTra inside it is free while that product's revenue is under USD 250,000, whatever the size of the company; above that it needs an Embedded licence. Internal use is defined to cover every part of ASTra (the MCP server, the CLI, the engine as a library and the validator), including scripts, CI/CD jobs and internal pipelines. An employee's use for an employer's work is the employer's use. Plans and prices are no longer listed in this repository; they are on attentionform.com/pricing. A person who works alone is free for their own work and client deliverables, but a product or service of their own with ASTra inside it that they offer to others is judged by that product's revenue like any other, and a competing offering needs a licence for one person as for a company. Every version released before this change keeps the terms it was released with. See `LICENSING.md`.

- **`tables` in `get_stats` and `astra stats` no longer counts callouts.** A callout is a one-cell table with a fill, so a document with one 3x3 table and one `> [!NOTE]` alert reported `tables: 2`. It now reports `tables: 1` and `callouts: 1`. The page estimate still weighs a callout like a table, so the number of pages does not change.
- **Alert callouts keep bold, italic, inline code and links.** A `> [!NOTE]` alert used to fail when its title or body held any of them. The title keeps its bold and the theme colour, and the body keeps its formatting. Images, raw HTML, inline math and footnote markers in an alert still fail with a line number. An alert of several paragraphs separated by a blank quote line no longer fails on the blank line. The `callout` operation accepts a client `id`.
- **The document title and creator come from the content.** A document from `new_document`, `compose_document`, `astra create` or `astra import` kept `dc:title` "Blank Document" (or "Report") and `dc:creator` "ASTra". When the title is still the name of a built-in template it is now written from the cover page title, else the first Title paragraph, else the first Heading 1. When an author is configured (`--author`, `ASTRA_AUTHOR` or the session author), the creator and `lastModifiedBy` follow it while the creator is still the tool default. A title the caller or the file already had is not touched.
- **`coverPage` on a fresh template removes the template's placeholder content.** After `new_document` and a `coverPage` batch, the file kept "Blank Document", "Start typing your content here..." or the sample report. On a document that is still an untouched built-in template the placeholders are removed once the cover is in place, and the result lists them as `removedSeedNodes`. A document that was edited first, or opened from a file, keeps all its content.
- **A dark header or cell fill gets readable text.** `setShading` with a dark `headerFill` left black text on it (contrast 1.18:1 for `0F172A`) and only warned. With no `textColor` set, the text is now white or black, whichever contrasts more, and the result carries a table note. A cell whose own text already reads well, a light fill and an explicit `textColor` are left as they are.
- **Saved and inspected tables keep their separators.** `save_document` showed a table as `VendorCostSLAAlpha1099.9` and `inspect_document` showed a callout as `Important Informationbody text`. A changed table now reads as rows with ` | ` between cells and a newline between rows, and the paragraphs of one cell are separated by a space.
- **Error messages name the real fix.** `inspect_document` with `limit` above 200 says to use `offset` and `nextOffset`. The sandbox remedies and the `new_document` description name the allowed folders (`--allowed-dir`, `ASTRA_EXTRA_DOC_ROOTS`) and say that `./documents` and the system temp folder apply only when none are named.
- **The tool list is shorter.** The workflow line and the unit rules were repeated in most of the 19 tool descriptions. The workflow line stays in `open_document`, `execute_batch`, `save_document` and `compose_document`, the unit rules stay in `execute_batch`, and the tool list goes from 85,664 to 78,179 characters.

### Fixed

- **`astra` and `astra-mcp-server` print and run on Windows.** The CLI started only when its path ended in `packages/cli/src/cli.ts`, contained `packages/cli/dist/` or was a file called `astra`. The npm shim on Windows starts `node <install folder>\dist\cli.js`, which matched none of these, so the command loaded the file and exited 0 without a word. Both built files now start when node runs them under any path or name.
- **A Windows drive letter is no longer read as a URI scheme.** The checks that refuse remote references matched the `C:` of `C:\Users\...`, so an absolute path to a picture, a chart file or a style guide was refused before the folder rule could look at it. `https:`, `data:`, `file:` and the drive-relative forms `C:` and `C:name` are still refused.
- **`--allowed-dir` accepts a folder that ends in a separator, and a filesystem root.** The folder rule compared against the folder plus a second separator, so a folder written with a trailing separator, and a root such as `/` or `C:\`, matched nothing and every file was refused with `E_SANDBOX`.
- **A cover page writes run properties in schema order.** `w:sz` came before `w:color`, so every `coverPage` batch listed three "Reordered w:rPr" lines in the normalized result.
- **The block list keeps the document order after an edit in the middle.** A block that an operation put in the middle of the document, with an id minted after the others, came last when a session rebuilt its AST from the live parser. The list is now put in the order of the document body.
- **`revert_document` accepts a version made before the document had core properties.** The restored package kept the live `docProps/core.xml` but not its content type and relationship, and the revert was refused as an invalid restore candidate. The part is now registered again after a restore.

## [0.3.0] - 2026-11-10

All ten npm packages move to 0.3.0, including the six native validator platform packages. The native validator source is unchanged; the platform packages are rebuilt so that they carry the licence terms for new versions.

### Added

- MCP review tools can list revisions and comments, inspect full revision or comment-thread text, search comments, resolve or delete comment threads, and accept or reject selected revisions. Tracked edits return their allocated revision IDs.
- **`astra sanitize --keep-revisions` and `--keep-comments`.** Each turns off one step of the metadata preset (accept the tracked changes, remove the comments) and changes nothing else, so the document properties, the authors and the edit-session tags are still scrubbed, and `word/people.xml` is still redacted when comments stay. They combine with `--metadata-only`, `--client-safe` and `--redact-pii`; the personal data inside kept deleted text and kept comments is then redacted too. `--keep-revisions` with `--accept-all-revisions`, and `--keep-comments` with `--strip-comments`, are usage errors (exit code 2) and write no file. A run that keeps something warns that the deleted text is still readable and that the revision and comment dates stay. Before, the only way to keep review history was a run that named no preset, such as `--strip-comments` alone, and the guide did not say so. `--json` carries `keptRevisions` and `keptComments`.
- The MCP startup line reports active filesystem roots. The default open summary includes counts, header and footer text, chart IDs, and whether revisions are pending.

### Fixed

- **`sanitize` no longer keeps the account id of a commenter when it keeps comments.** A run with `--zero-retention` or `--replacement-author` and without a preset keeps the comments and `word/people.xml`. The author name in that file was emptied but the account id (`w15:userId`, for example an email address or a Windows SID) was left as it was. It is now redacted. Bare `sanitize`, `--metadata-only`, `--client-safe`, `--redact-pii` and any run with `--strip-comments` remove the part and were not affected.
- **The `sanitize` warning counts comments, not their markers.** `comments (4) survive` was printed for a file with one comment, because the count added the range start, the range end, the reference and the definition of each comment. It now counts comments, so one comment is reported as one.
- **Paragraphs with text boxes and drawings can be edited.** Text kept inside a text box or drawing (Word's `mc:AlternateContent`, VML or DrawingML) is counted, so an edit outside the box no longer fails with "the paragraph text and text map differ", and the box text is kept. A tracked delete of the whole paragraph may wrap the box; any other edit that would cut or remove box text is refused with a reason. A paragraph that holds the start or end of a field that spans paragraphs (a table of contents) or an inline partial move is refused with a precise message.
- **Accept and reject read the current header, footer and note parts.** The parts were cached and never refreshed, so an edit to a header or footnote followed by `acceptAll` could be silently reverted and a rolled-back batch could leave the revision count wrong.
- **New revision IDs are exact and clear of move markers.** IDs now start above the IDs on `moveFrom`/`moveTo` range markers, which share the ID space. An ID that cannot be held exactly (at or above 2^53 - 1) fails with `E_VALIDATION` and changes nothing. Every tracked edit returns the IDs of the revisions it creates: `insert`, `delete`, `replace` (including the paths that keep or rebuild runs) and table `updateCell`.
- **`sanitize` with `acceptAllRevisions` no longer returns a partly cleaned file.** Before, revision markup the resolver could not handle had its author and date stripped, which produced invalid files and still left deleted text. Now the sanitizer refuses with `E_VALIDATION`, names the part and the kinds that remain, and returns no file.
- **Accept and reject resolve whole paragraphs as Word does.** A whole-paragraph move (as desktop Word writes it) is resolved at both ends together, with no empty paragraph left behind. A paragraph whose mark and content are one deletion or one insertion is removed as a unit; bookmarks wholly inside it go with it, and a comment thread anchored only inside it is deleted with it (a comment that is also anchored elsewhere leaves the paragraph unresolved and reported). A tracked table of contents inserted as a block is kept or removed as one unit. `revisionResolution` lists `removedBookmarks`, `removedComments` and `staleLinks`. A table-of-contents entry that still links to a removed bookmark stays, as in Word.
- **Comment threads work for every comment shape.** A thread is identified by its last paragraph, so replies, resolve and delete work for comments with several paragraphs and for comments from Word 2007 and other generators that have no extended comment parts. Comment operations accept `3` or `comment:3`. Deleting the last comment removes the comment parts, as Word does. Comment search returns `truncated: true` when more than 50 matches exist.
- **`sanitize` removes the comments of paragraphs it deletes.** With `acceptAllRevisions` (also bare `sanitize`, `--client-safe`, `--metadata-only` and `--redact-pii`), accepting a deleted paragraph that carries a comment now deletes that comment thread, and drops the comment parts when no comment is left. Before, the comment text stayed in `word/comments.xml` with no anchor. A thread that is also anchored outside the deleted text makes the sanitizer refuse with `E_VALIDATION` and write no file; add `stripComments` to remove all comments.
- **`stripComments` removes every comment part.** `commentsIds.xml` and `commentsExtensible.xml` (which holds comment timestamps) were left in the package after the comments were stripped. They are now removed with the other comment parts.
- **Saving keeps the content types of `commentsIds.xml` and `commentsExtensible.xml`.** Both were rewritten to the plain comments content type, which made every Word 2016 or later file with comments fail validation after a save.
- **A tracked replace no longer gives two runs the same revision ID when it splits a run that carries a tracked formatting change.** Splitting a run with `w:rPrChange` copied the record, with its ID, onto every part, and the validator rejected the file (`Sem_UniqueAttributeValue`). Each copy now gets a new ID, with the author and date kept. Text that an edit inserts no longer claims that a reviewer changed its formatting. This was also wrong in 0.2.x.
- **Paragraphs with range-permission markers, bidirectional wrappers and custom XML can be edited again.** `replace` and tracked `delete` refused paragraphs with `w:permStart`/`w:permEnd`, `w:bdo`, `w:dir` or `w:customXml`, although 0.2.x edited them correctly. Edits now go around the markers and inside the wrappers, and the wrapper is kept when you accept or reject the change.
- **Paragraphs with ruby text (furigana) give the right message.** The refusal said "unsupported field marker", which is wrong. Ruby text is now one block that an edit may not cut. An edit around it works and the ruby text is kept on accept and reject. An edit that would cut it is refused and the message says so. 0.2.x lost the ruby text silently.
- **Accept All removes a deleted paragraph whose deleted text sits inside a link, smart tag, bidirectional wrapper or custom XML.** The paragraph stayed as an empty paragraph. This was also wrong in 0.2.x for links and smart tags.
- **A tracked delete or replace that covers a simple field no longer damages it.** In 0.2.1 such an edit returned success, but the file was wrong: the field was left in the paragraph, emptied and moved in front of the text, and only its cached result was tracked as deleted, so Accept All kept the field. The field (`w:fldSimple`) is now rewritten as the complex field Word writes for it (begin, instruction, separate, result, end), and each part is tracked as a deletion. Accept All removes the field. Reject All brings it back as a complex field with the same instruction, result and formatting; the original `w:fldSimple` markup does not return, and Word treats both forms as the same field. The edit is refused, and nothing changes, when the field result holds a link, a tracked change or another wrapper, or when the edit covers only part of the field. A replace that keeps a word or a space of a multi-word field, such as a date, counts as covering part of it; the message now says to change all of the text of the field in the same edit (before, it said to replace the paragraph, which gives the same change). Untracked edits and tracked edits outside the field leave simple fields as they are.

### Changed

- **`inspect_document` pages review records separately from nodes.** `offset` and `limit` now page document nodes only; the `include` lists of comments and revisions page with the new `reviewOffset` and `reviewLimit` (at most 50). Before, one `offset` moved both. A node `offset` past the last node is rejected whether or not `include` is set, and `commentId` or `revisionId` without its matching `include` is rejected instead of being ignored. Callers that paged review records with `offset` must switch to `reviewOffset`.
- **Pending revisions are counted and reported honestly.** `revisionsPending` counts every revision element left, so a move counts as each of its markers. After an accept or reject that left revisions it could not resolve, the new `revisionsUnresolved` counts them and `revisionsRemedy` lists their kind, node and reason instead of telling the caller to run `acceptAll` again.
- **Selective accept and reject are faster on large documents.** A run of accept and reject operations refreshes the session's view of the document once instead of after each operation. On the same workloads the batch took 3.4 to 4.1 times less time (1,500 paragraphs, 50 selective accepts: 6.1 s to 1.5 s); the results are identical. A block's version is raised once per run, not once per operation.
- **Accept and reject skip the refresh of the session's view when no revision was resolved.** Accept All on a document with no pending revisions re-read the whole document for nothing. On 3,000 paragraphs the call took about 300 ms and now takes about 105 ms. When revisions are resolved, the refresh is still needed; it is faster since the next two entries.
- **Opening a document and refreshing the model are faster.** The checksum of each block used `crypto.subtle.digest`, one separate job per block (about 125 ms for 3,000 paragraphs, paid on every open and after every accept, reject or rollback). It now uses Node's synchronous SHA-256 (2 to 5 ms) and returns the same value, so no stored or compared checksum changes. The engine exports `calculateNodeChecksumSync` next to `calculateNodeChecksum`. On a document of 3,000 paragraphs (median of five runs, three runs per build): opening takes about 55 ms instead of about 205 ms; Accept All with 300 pending revisions takes about 140 ms instead of about 300 ms, Reject All about 145 ms instead of about 320 ms, and a document in which every paragraph is revised about 350 to 380 ms instead of about 580 to 620 ms. The 0.2.1 engine does the same Accept All in about 100 ms, Reject All in about 105 ms and the every-paragraph case in about 295 ms, because its resolver does less (it does not resolve moves, whole paragraphs or bookmarks as Word does). What remains above that is the resolver's own work and the copy of the document that every batch takes for rollback.
- **Counting revisions and finding the highest revision id walk the document once.** Both walked it once per element name (29 walks, 17 ms on 3,000 paragraphs, and the count is repeated after every batch). They now take one walk (about 1 ms) and return the same numbers. A deeply nested document cannot overflow the stack.
- **`sanitize` presets accept tracked changes (a warning, no change).** Bare `sanitize`, `--client-safe`, `--metadata-only` and `--redact-pii` accept all tracked changes and remove all comments, so the deleted text and the review history are not in the output. The input file is never changed. This is how earlier versions behave. To keep tracked changes or comments, add `--keep-revisions` or `--keep-comments`. The MCP `sanitize_document` tool does not do this by default: it keeps tracked changes and comments, with the text of every tracked deletion, unless `acceptAllRevisions` or `stripComments` is passed. Its tool description said otherwise and now matches.
- **Refusals name a remedy that works.** An edit that touches an inline content control or an equation is refused as before, but the message no longer tells you to replace the paragraph (that is refused too). It now says to edit the text outside the control or equation, to delete the whole paragraph with `trackChanges` false, or to use Word. The same holds for a tracked edit that covers a simple field whose result is not plain runs. The refusals for fields that span paragraphs and for partial moves no longer add a second remedy.
- **Documentation: the refused and unresolved cases are listed.** `docs/mcp-specification.md` now states which edits are refused (inline content controls and equations, a simple field whose result is not plain runs, the start and end of a field that spans paragraphs, partial moves) and which revisions stay unresolved (a deleted paragraph whose bookmark runs into another paragraph, rejecting `customXml` range markers, incomplete moves).
- **`astra sanitize` names `metadataOnly` only when `--metadata-only` was given, and says what `--metadata-only` removed.** The result line printed `metadataOnly` and `--json` carried `metadataOnly: true` for every run that did not redact the body (bare, `--zero-retention`, `--replacement-author`), although the run had not used the flag. Both now appear only when the flag was passed. A run with `--metadata-only` that accepted tracked changes or removed comments also prints one note on stderr that says so and names `--keep-revisions` and `--keep-comments` (not with `--json`). The body-PII warning no longer tells a run that did not use `--metadata-only` to re-run without it. The output files are unchanged: a comparison of 190 runs (19 flag sets, text and `--json`, 5 documents) gave the same files and exit codes before and after.
- **Documentation: `--metadata-only` matches the code.** `docs/cli-guide.md` said `--metadata-only` keeps tracked changes. It is the same as bare `sanitize`: comments are scrubbed and tracked changes are accepted. The command did not change; a test now guards the documented behaviour.
- `open_document` returns a compact summary by default. Pass `summaryOnly:false` for the former full structural summary and styles XML.
- Tracked deletion honors the requested text and requires `occurrence` when the text appears more than once. Paragraph edits preserve unchanged run formatting and refuse unsafe spans rather than silently flattening them.
- Accept and reject handle additional revision kinds and document parts, report unsupported revisions, and refresh the session view. Sanitization uses the same revision resolver. New revision IDs are allocated across the package; imported IDs are preserved.
- MCP tool schemas share repeated definitions. Stack traces are logged only when `ASTRA_DEBUG` is set.

Markdown compilation now preserves the exact character offset of each reference marker, and the `footnote` and `endnote` operations accept an optional `offset` field (integer character index into the anchor paragraph text) to place the reference run in-place, splitting runs while preserving bold and italic character properties on both sides.

The MCP tool description and schema are updated to match.

Similarly, `--strip-macros` targeting `.docm` is refused because Word expects a macro-enabled document to retain macro parts. MCP `save_document` enforces the same guard against saving macro parts to `.docx`.
- **A table written by `insert` has space above and below the text in its rows.** The rows had none (the Normal Table style sets 0), so the text touched the lines. A table without `cellPadding` now gets 3 pt (60 twips) above and below; the sides stay with the style (0.075 in). A caller that passes `cellPadding` gets exactly what it asked for, and so do tables composed from Markdown. The test that pinned the old output ("byte-identical without `w:tblCellMar`") now pins the new one. A table that is already in a document is not changed.

Compose already did this for Markdown. The operation engine now does it for every path (`batch`, MCP `execute_batch`). A block that names a paragraph style, already has space above it, or is a page or section break is left alone, and a `style` operation can change the space afterwards. A document that is already built is not changed.

A callout is a one-cell table. When an `insert` of a table or a `callout` leaves it right before or after another table, the engine now adds an empty paragraph between them, whether the document is built with operations (`batch`, MCP `execute_batch`) or composed from Markdown. The paragraph is an ordinary one: a `style` operation can change its spacing and a `delete` removes it, and the engine does not put it back. A document that is already built is not changed.
- **A code block's box sits on the text margins.** The paragraph border is drawn outside the indent by its `w:space` (4 pt), and the block had a left indent of 180 twips and none on the right, so Word drew the box 5 pt inside the left margin and 4 pt past the right margin. The indent is now 80 twips on both sides. A code block that is already in a document is not changed.

Word updates fields on open (`updateFields`), and it then built a second table of contents beside the baked one. With no cut the footer is unchanged (`7 matches`).

Manuscript imports start at paragraph 1 with references starting strictly at index 1 without numbering offsets.

A NOTE on stderr now names what the check looks for (email addresses; phone numbers, formatted or after a label such as `phone`; US Social Security numbers; runs of 13 to 19 digits) and what it does not (other national ID numbers such as CPF and CNPJ, names, addresses, unlabeled digit runs), and says that `pii` counts document properties and `bodyRedactions` counts body text. A bare or `--metadata-only` run says that the body was not checked. `--json` carries the same lists as `piiCoverage`, and the `sanitize --help` text states the limits. A test checks that every named family is redacted and that CPF, CNPJ and unlabeled digits are left alone, so the note cannot drift from the patterns.

This holds for `astra export` and for MCP `export_document`. The engine exports `htmlDocumentTitle` for callers of `convertAstToHtml`.

For a key the action does not accept (`spaceAfter` on `style`), it names the closest key (`"spacingAfter"`) and lists the keys the action takes. For an unknown operation name (`addRows` on `table`) it names the closest one. The CLI points to `astra batch --schema`; MCP `execute_batch` gives the same hints. The engine exports `operationIssueRemedy` and `closestNames`, which read the operation schema, so the lists follow it.

A document that is opened is not changed.

It now matches a section id or a node id exactly, and takes a node id prefix only from 4 characters on; any other id is an `E_VALIDATION` error that lists the section ids (the first 20 and a count) with the remedy once, at every tier. The footer of `astra inspect` shows the ids: `sections=3 [sec_root, sec_2, sec_3]` (the first 8 and a count), and `--json` carries `sectionIds`. A one-, two- or three-character node id prefix no longer selects nodes.

Word does not open a `.docx` that holds macro parts, and the command wrote one without a word. Nothing is written when it refuses. With `--strip-macros`, or on a file without macro parts, the output name is not checked.

The output is never the same file as the input, with or without `--force`, whether it is the same path, a link to it or a second name for it. Scripts that ran `sanitize` over an existing output need `--force`.
- **A save repairs paragraphs that share a `w14:paraId`** instead of refusing the file (about 0.15 to 0.5 % of documents). The first paragraph keeps its id, each later copy gets a new unique id, and the mirrored copies Word writes in `mc:Choice` and `mc:Fallback` are left alone. Each change is listed in `normalized` (`Renumbered duplicate w14:paraId "<old>" to "<new>" at <xPath>`). The state before is recorded in the history, so one `revert_document` / `astra revert` returns the repeated ids: MCP `save_document` creates the history if needed, CLI `batch` records it when a history repository exists and the result goes into the input file. `--strict` (CLI) and `strict` / `--strict-validation` (MCP) keep the refusal. The library default of `DocxParser.rezip()` is unchanged (refuse); `rezip({ duplicateParaIds: 'renumber' })` and `setDuplicateParaIdPolicy` opt in.
- **Saving a document that already has validator errors.** `open_document` reports the file's validity and never refuses the open. A save is allowed when it adds no error beyond the ones the file had; `strict` (`--strict-validation`, `ASTRA_STRICT_VALIDATION=1`, CLI `--strict`) keeps the earlier behavior. The validator list is no longer cut at 200 errors for this comparison.
- **`normalize` repairs known validator error kinds**: element order in settings, styles, section properties, tables and runs; decimal values in integer attributes; on/off attribute values; smart tags; duplicate shape types; a `w10:wrap` of type `inline`, which is not a wrap type (removed); a `w:color` without a value (set to `auto`); and a few others. A repair that changes the visible text or adds an error is dropped. The output gains `remaining` and `rolledBack`. `--dry-run` does not run the repairs. With a history repository, `normalize` commits the state before the repairs (when it differs from the head) and then the result, so one revert returns the original; `--no-history` turns this off.
- **`revert_document`, `redo_document` and CLI `revert`/`redo` restore a recorded state that carries validator errors.** Before, they refused any restored state with an error, so a file that was repaired could not be reverted to the original. MCP allows the errors of the file as opened and of its saved state; CLI allows the errors of the recorded state and refuses only a result that cannot be compared.
- **`--allowed-dir` names the whole boundary.** The system temp folder and `documents/` are no longer added. A symbolic link at or above a named folder no longer blocks writing; a link below it that points outside it is still refused.
- **`astra batch` records a history revision** when the document has a history repository and the result is written to the input file. `--no-history` turns it off.

### Fixed

- **HTML and Markdown export do not leak rows of nested tables into outer tables.** In tables without cell merges, row and cell extraction previously used `getElementsByTagName` which descended into nested tables, appending their rows and cells into the outer table. Both exporters now use `ownElements` to restrict extraction to the table's direct rows and cells, matching the behavior of merged tables.
- **`normalize` repairs misplaced and doubled `w:pPr`, and out-of-order `w:tcMar` cell margins.** A paragraph whose `w:pPr` is not its first child has it moved to the start. A paragraph with two `w:pPr` keeps the last and drops the earlier one, because that is what Word shows and saves (checked on 97 paragraphs of a corpus document; the 97 validator errors for them are gone and every paragraph keeps the style Word gives it). A paragraph with three or more `w:pPr` is left as it is. `w:tcMar` children are put in schema order. Open and `sanitize` do not repair anything; run `normalize`, and one revert undoes it.
- **A style operation names the keys it ignores.** A key inside `params` or `properties` that is not a style key (for example `spaceAfter`, for `spacingAfter`) is still ignored, as before. The operation now says so in its warnings, with the closest style key when there is one, also when other keys in the same bag are valid. When no key in the operation applies, the operation is refused and the message names the closest style key.
- **`normalize` repairs three more kinds of validator error.** (1) A `w:tcPr` with more than one `w:vAlign` keeps the last one (the one a renderer applies last); the corpus document that has 28 such cells renders the same on all 23 pages before and after, in LibreOffice. (2) An empty `w:fill=""` on `w:shd` is removed, which means no fill; LibreOffice drew such cells black, so a calendar in the corpus showed white text on black until it was repaired. (3) The settings order now ranks Word's `w14:docId`, `w14:discardImageEditingData`, `w14:defaultImageDpi`, `w15:chartTrackingRefBased` and `w15:docId` after `w:listSeparator`. Before, `normalize` moved `w:listSeparator` behind them and made the order invalid. Word has not been used to check the first repair: when two `w:vAlign` conflict, Word may apply the first instead of the last.
- **`astra batch --schema` shows every kind of operation.** It listed 20 examples and none for `clearFormat`, `section`, `pageSetup`, `field`, `equation`, `headerFooter`, `image`, `watermark`, `pageBorder`, `coverPage`, `hyperlink`, `bookmark`, `trackedChange` or `metadata`, nor for the table operations `addRow`, `addColumn` and `mergeCells`, and the `style` example had no spacing keys. Each is added, and the image example states that width and height are in EMU. The `move` example now uses `<otherNodeId>` for the anchor, so it no longer names the same node twice. A test checks that every action of the operation schema has an example, that every example passes the schema gate, and that each example that does not depend on an earlier operation runs on a real document.
- **`create` and `import` help say when an italic line becomes the Subtitle.** A line that is only italic, directly under the opening `#` title, gets the Subtitle style and loses its emphasis (the style is already italic). The help and `docs/cli-guide.md` now state this, and how to keep an italic body line there: put another paragraph first or add plain text to the line.
- **HTML and Markdown export show italics that come from a style.** A Subtitle or Quote paragraph is italic through its paragraph style, with no `w:i` on any run, and both exports read run properties only, so that text came out plain. Italic is now read from the run first (`w:i` on or off decides alone), then from the paragraph style and the character style, which toggle each other as in Word; within one style the closest definition in the `w:basedOn` chain wins. Markdown also writes neighbouring runs with the same bold and italic as one span, so `*a**b*` no longer occurs. An export called without a parser reads direct formatting only, as before.
- **HTML and Markdown export keep merged cells.** A table with `w:gridSpan`, `w:vMerge` or `w:hMerge` exported one cell per stored cell with no spans, so the columns slid out of line (for the engine's own `mergeCells`, the text of the covered cell also appeared as a separate cell). HTML now writes `colspan` and `rowspan` and leaves covered cells out; the rows that a header cell spans stay in the table head. Markdown writes the text of a merged range once, in its first cell, with the other cells of the range empty, and adds one line under the table that says Markdown cannot show merges. The text of a cell that was merged in from the same row is joined to the merged cell, as the renderer shows it; the text of a cell merged in from below stays hidden, as it is there. Cells inside a content control are read too. Tables without merges export exactly as before. Checked on the 46 corpus documents that have merges (223 tables): every table whose rows add up to the same width in the XML keeps that width.
- **The page estimate no longer counts a page after the last node.** A node that filled its estimated page opened the next page at once, so a document whose last node ended a page got one page too many, with a `Blank page` warning for it. The total (`totalPages` of the structural summary, the page estimate in `buildPageMap`, and `[PAGE n OF m]` in the visual telemetry) is now the highest page that holds a node, and the blank-page warning covers only a page below the last populated page. The CLI and MCP visual telemetry also read the summary's page-map source, so an estimated map is labelled `(estimate)` (it was always called a renderer map). The label is left off when the render's own count replaces the estimate. A render that has more pages than the estimate now prints the `Pagination mismatch` note where the extra page used to hide it.
- **`stats`, `search`, `export`, `normalize`, `history`, `preview-revert`, `revert` and `redo` take `--allow-macros` and `--strip-macros`.** A document with macro parts is refused by these commands, and the refusal told the user to pass flags that the commands did not accept. They now take the flags the way `inspect` does (both together are a usage error). `export` applies them to HTML and Markdown; a PDF export never opens the macro parts. `normalize --allow-macros` refuses an output that is not `.docm` or `.dotm`, and `normalize --strip-macros` refuses a `.docm` or `.dotm` target (use `--out <name>.docx`), both before anything is written. `revert` and `redo` refuse `--strip-macros` for a `.docm` or `.dotm`, because they write the file in place. The `normalize` refusal keeps the macro remedy instead of the generic one.
- `table` with `addRow` accepts `cells` flat on the operation (`{"action":"table","operation":"addRow","cells":["a","b"]}`), as well as inside `params`. The strict schema rejected the flat form with `Unrecognized key: "cells"` although the engine already read it. Up to 100 entries of up to 100,000 characters.
- `footnote` and `endnote` no longer make the file invalid when `word/settings.xml` already lists the separator references (`<w:footnote w:id="-1"/>`) in `w:footnotePr` or `w:endnotePr`, which Word writes. The `w:numRestart` element was added after them; it now goes before them. About 47 % of corpus documents were affected, and the CLI and MCP refused the edit on them.
- Run properties keep the Word 2010 text effects (`w14:glow`, `w14:shadow`, `w14:reflection`, `w14:textOutline`, `w14:textFill`, `w14:scene3d`, `w14:props3d`, `w14:ligatures`, `w14:numForm`, `w14:numSpacing`, `w14:stylisticSets`, `w14:cntxtAlts`) after every `w:` property, in that order, before `w:rPrChange`. Before, they kept their place while the other properties moved around them, so a style edit such as bold could put `w:lang` or `w:szCs` after a `w14` element and make the file invalid (9 corpus documents). `normalize` applies the same order. `clearFormat` now also removes these text effects, as Word's Clear All Formatting does.
- An image insert, and a save of a document that holds an image part, no longer add `<Default Extension="png"/>` when the package already declares `PNG` (or any other extension in different case). Package extensions are not case sensitive, so the two lines were a duplicate and the validator could not open the package.
- `headerFooter set` edits the existing header or footer when its relationship target is an absolute part name (`/word/footer1.xml`, which some writers use). Before, the text went into a new part `word/word/footer1.xml` and the real footer stayed as it was, while the operation reported success (6 of 695 corpus documents).
- `bookmark` (and its `name` alias) works on a paragraph that has no `w:pPr` of its own but holds a text box or drawing whose inner paragraph has one. It looked for the first `w:pPr` anywhere inside the paragraph, found the inner one, and failed with `Not found: child not in parent` (10 of 695 corpus documents). It now uses the paragraph's own `w:pPr`.
- `watermark` no longer adds a second `<v:shapetype id="_x0000_t136">` to a header that already declares one, for example a watermark made in Word. A shape type id may appear once per part, so the file was invalid (2 corpus documents). When the header relationship target is an absolute part name (`/word/header1.xml`), `watermark` also keeps the text already in the header; before, it did not find the part and replaced the header with the watermark alone.
- `--strip-macros` on a macro-enabled document (`.docm`) now leaves a plain document package. It also removes the rels part of the removed `vbaProject.bin` and the `word/vbaData.xml` part named there, changes the main part's content type from macro-enabled to plain document, and drops the `vbaProject` default content type when no `.bin` part is left. Before, Word refused the stripped file.
- The characters U+2028 (line separator) and U+0085 (next line) in the text of a document stay as they are on open and save. The XML parser turned both into a line feed, so a document that held either character came out of a save, even a no-op one, with different text (about 7 of 101 documents in the corpus sample). The engine now parses every package part through `ooxml/dom-parser.ts`, which writes both characters as character references before parsing. Comments, CDATA sections and processing instructions are left alone.
- A package without `[Content_Types].xml` is refused at open, like a package without `word/document.xml`: `E_VALIDATION: Invalid DOCX: missing [Content_Types].xml`. Before, `open`, `batch` and `inspect` accepted it, edited it and saved it still broken, while a dangling relationship was refused (about 2,883 of 2,887 damaged copies in the corpus test). `astra validate` still reports such a file as INVALID, with the validator's own error list. Nothing is regenerated or guessed; a file that can be salvaged has to be repaired elsewhere first. A test that built its package by hand without the part now adds it.
- Edits are no longer refused on documents with more than 1,000 validator errors (about 6 of 2,868 corpus documents). The Open XML SDK stops at 1,000 errors without saying so, so the file before and after an edit showed two different sets of 1,000 and the difference looked like new errors (`this edit adds 586 validator error(s) (the file already had 1000)`). The validator worker now sets the SDK limit from the request: a request for more than 1,000 errors gets them, and a list cut at the requested number is marked `truncated`. The comparison asks for up to 50,000 errors. The validator also treats the three element-content errors the SDK reports for one element (`unexpected`, `invalid` and `incomplete` content) as one fault: putting the children of an element in schema order cleared the first and showed the second at the same element, and that was counted as a new error. A document with more errors than the limit is still not compared and the edit is refused.
- Table, image and chart operations are no longer refused because of a fault the document already had. The structural check after a batch (a table without rows, a row without cells, a cell without a paragraph, a `gridSpan` of 0, a drawing without its wrapper, extent or graphic, a chart reference without `r:id`) now looks at the faults the batch added. A document with one malformed table takes an edit to another table (about 26 of 2,868 corpus documents were refused). An edit that breaks a table, or makes a new broken one, is still refused and rolled back, with the same message.
- `sanitize` with PII redaction no longer changes the numbers in a chart. A value that is only a decimal number (`0.1234567890123`, `6.2322946175637411E-2`) in element text or an attribute was read as a card number and became `0.[redacted]`, which made the chart layout invalid and removed its data (2 of the corpus documents, 163 redactions). Such a value is now left as written. Card, phone and social security numbers, and text around a number, are still redacted.
- `sanitize` with zero retention (the default for a bare `sanitize`, and `--strip-macros` runs it) no longer leaves empty `dcterms:created` and `dcterms:modified` elements in `docProps/core.xml`. An empty date is not a valid W3CDTF value and Word refused to open the file ("The file appears to be corrupted"). Both elements are now removed.
- Saves and inserts on large documents no longer take quadratic time (live node lists, repeated paragraph-id scans, a second serialization of the main document).
- `numbering.xml` keeps its root element and extra children; the normalizer no longer moves elements it does not list; paragraph ids shared by `mc:Choice` and `mc:Fallback` are no longer reported as duplicates.
- `--strip-macros` removes the references to removed parts, so the result validates.
- Parts stored in UTF-16 are read as UTF-16; the XML safety check looks at markup only, so text that mentions XSLT is no longer refused.
- `dedupeDrawingDocPrIds` gives the same result on every pass for nested drawings.
- A `bookmark` created with `name` gets that name; before, the executor read only `bookmarkName`. When both are given, `bookmarkName` wins.

## [0.1.0] - 2026-10-31

First public release.

### Added

- **Engine** (`@attentionform/astra-engine`): reads a `.docx` into a structured document with stable node ids; 27 typed operations (insert, replace, delete, style, tables, sections and page setup, headers and footers, fields, equations, lists, charts, images, callouts, footnotes and endnotes, watermarks, page borders, cover pages, hyperlinks, bookmarks, comments, tracked changes, metadata); batches that apply all or nothing; revision history.
- **Validation on every write.** A file is checked against the Office Open XML schema before it is written. An invalid result is refused with `E_VALIDATION`, an explanation and a suggested fix, and the file on disk is left as it was. This covers `save`, `sanitize` and PDF export.
- **Schema validator** (`@attentionform/ooxml-validator`): the .NET 10 Open XML validator behind the check above, with a persistent worker process, in-memory validation without temporary files, and prebuilt binaries for Linux, macOS and Windows on x64 and arm64.
- **MCP server** (`@attentionform/astra-mcp-server`): 19 tools over stdio, including open, inspect, search, execute a batch, save, compose from Markdown, import, export (HTML, Markdown, PDF), visual inspection, history, preview and revert, validate, statistics, sanitize and normalize. Every call is confined to the folder given with `--allowed-dir`.
- **Command line** (`@attentionform/astra`): 15 commands for scripts and pipelines, with a machine-readable `--json` output and documented exit codes.
- **Equations.** LaTeX in documents becomes native Word equations, including accents (`\dot`, `\ddot`, `\hat`, `\bar`, `\vec`, `\tilde`), and round-trips back to LaTeX. In Markdown, `\( \)` and `$$ $$` are always math; `$ $` is math only when you turn it on, so prices such as "$5 and $10" stay text.
- **License and contributions.** ASTra is source-available under the Business Source License 1.1 (`BUSL-1.1`). Free production use covers individuals (including freelancers and consultants), schools and academic research, non-profits, public bodies and small businesses; other production use needs a commercial license. Each version becomes Apache-2.0 four years after it is first made public. Outside contributions require a one-time contributor license agreement, signed by adding a signature file to the first pull request and checked by the `cla` workflow (see `CONTRIBUTING.md`).
- **Privacy tools.** `sanitize` removes document metadata by default; `--redact-pii` and `--client-safe` also redact personal data in the body text. Footnotes and endnotes are preserved.
- **Numbers count from 1.** Every number you type or read starts at 1: table rows and columns (`rowIndex`, `colIndex`, `index`, `afterIndex`, merge ranges), chart series (`trendline.series`), sections (`sectionIndex`), list levels (`level`, shown as `[L1]` in `inspect`) and pages. `inspect` prints the same numbers it accepts. `0` is refused with the valid range; for list `changeLevel`, `0` takes a paragraph out of its list. `offset` (how many items to skip) and the raw file values stay 0-based.
- **Cell addresses.** A table cell is addressed as `<tableId>:r<row>c<col>` (for example `t_001:r2c3`), or `…:p<n>` for one paragraph inside it. `replace`, `style`, `namedStyle`, `clearFormat`, `hyperlink`, `bookmark` and `comment` accept it as `target`; any other action refuses it and names the fix. `search_content` can return cells, and `compose_document` returns a `persistentIds` map from its temporary `md_*` ids to the ids the saved file carries.
- **Unknown settings are refused.** An operation that carries a setting it does not read (for example `bold` inside `params` of a table `updateCell`) fails with `E_VALIDATION` before anything is applied, naming the setting and the ones that are accepted.
- **Real dates and your own author.** Output carries real timestamps by default. For byte-identical output pass `--reproducible` (or set `ASTRA_REPRODUCIBLE=1` or `SOURCE_DATE_EPOCH`); `ASTRA_NO_REPRODUCIBLE=1` wins over both. `--author <name>` sets the default author for tracked changes and comments that do not name one.
- **Better defaults when composing Markdown.** Composed tables get a navy, bold header row and striped body rows (a row added later keeps the stripes, and deleting a row re-alternates them); a subtitle under the title is kept. The old plain look is still available as the `legacy` style. `headerBold` (default on) turns the bold header off, flat or in `params`, or with `- Header Bold: false` under `## Tables` in a style guide. Spacing and indents accept twips or a point string such as `"12pt"`.
- **Complete new files and a safe history location.** New documents carry the full package (document properties, settings, font table and theme) and pass the Open XML SDK validator. `ASTRA_HISTORY_DIR` keeps revision history out of the document's folder.
- **Visual output.** `visual_inspect` takes `outputDir` to choose where page images are written (a symlink at the image name is refused). The text wireframe shows table columns, the header and first rows, list markers and `[CALLOUT]` blocks in about 380 tokens.
- **Lists have nine levels.** A new list definition carries all nine levels, so an item at any level has its marker and indent: bullets cycle `•` `◦` `▪`, numbers cycle `1.` `a.` `i.`. Before, only level 1 was defined and a deeper item had no marker or indent of its own. A list is reused only when its top level is the requested kind (a Word list that is numbered at level 1 and bulleted at level 2 used to be handed out for a bullet list), never when it is heading numbering or a style link, and a list that stops short of the level an item is placed at gets the missing levels in place.
- **`pageSetup` turns the page.** `orientation: "landscape"` (or `"portrait"`) now swaps the section's width and height, so the page really turns in Word and LibreOffice; before, only the orientation flag changed unless a `paperSize` was given too. Margins are written as given, never rotated. A `paperSize` given alone keeps the section's orientation.
- **`validate` lists the repairs a save would make.** `astra validate` and `validate_document` report `pendingNormalizations` (for example property children that would be put back in schema order) next to the verdict, so a file that is valid only once ASTra has saved it no longer reads as plainly valid.
- **Sections are read from the file.** A document opens with the sections it has: one per section break, with its own page setup, ids `sec_root`, `sec_2`, `sec_3`, … by position, and `inspect` reports the real count (it always said 1 before). Section operations, headers, footers, page borders and columns work on a file you opened, not only on sections made in the same session. A header kept only for a later section's first page is no longer typed as the document header.
- **New content goes where the file puts it.** With no anchor, an insert, table, callout, table of contents, field or chart goes to the end of the document (it went into the first section before, and a callout or table of contents with no anchor crashed on a document with several sections). Content placed right after a section break paragraph starts the next section. `equation` and `move` follow the same rule.
- **A failed batch changes nothing you can see.** The ids and versions returned by earlier batches (`_bk_new_…`, `md_…`, section ids) still resolve after a failed batch, a dry run or a failed single operation, and an `expectedVersion` taken before the failure is still valid. If the document cannot be matched block for block, the error says the ids were re-read.
- **Sections follow the section breaks.** After every batch, if a section break was deleted, moved or added, the sections are rebuilt from the document and the result carries a warning. Deleting a break merges the section into the next, as in Word; the text takes the page setup of the section after it. The header and footer of a deleted section are removed from the file too, with any picture only they used, so their text does not stay inside the saved document; nothing is removed while anything still refers to it, and if the package would be left with a broken reference the removal is skipped.
- **Headers, footers, page borders and columns fail loudly.** When a section has no section properties to hold the change, the batch fails and rolls back; before, it did nothing and a header or footer part could be left behind. A header or footer can now be set on an empty trailing section.
- **One Node version for every package.** The validator wrapper needs Node 22.19 or newer, like the engine, the command-line tool and the MCP server (it said 20 before).
- **Validator binaries keep working when one platform's build fails.** The native binaries have their own version, separate from the wrapper's, and the wrapper accepts a range of them, so a platform whose newest binary could not be published keeps its last one.

### Security

- The model can no longer approve its own shell commands; approval always comes from the person at the keyboard or from an explicit flag.
- Archive entries, XML external entities, decompression bombs and active content are rejected or removed (see `docs/security.md`).
- Dependency advisories resolved before release: `zod`, `undici` and `@vitest/mocker`.

### Requirements and validation

- PDF export and page images need LibreOffice and Poppler installed on your machine.
- Every output file is validated with the Open XML SDK before it is saved, so files are valid, uncorrupted and open in Microsoft Word.
